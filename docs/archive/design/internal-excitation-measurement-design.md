# 内部励起測定設計ドラフト

ステータス: ドラフト / 未確定 / ハードウェア未検証

本文書は、次期 VAMeter-Edu の内部励起測定設計を整理するための設計ドラフトである。
ここでの内部励起とは、内部電源により負荷へ電力を供給できるアクティブ出力を指す。
本文書は回路方式、部品、ファームウェア、CSVスキーマ、UIを確定しない。

## 1. 目的

次期 VAMeter-Edu は、内部電源付き V-I 実験器 / V-I ロガー / 発熱実験ロガーを目指す。
そのため、内部励起出力、電圧・電流測定、保護、CSV記録、QR/ローカル転送を混同しない設計境界が必要である。

本ドラフトの目的は次の通りである。

- 内部励起時に何を測っているかを明確にする
- 測定パスと出力パスを混同しない
- 保護をファームウェアだけに依存させない
- 理科 / 技術科 / 発熱実験ロガーの違いを設計に反映する
- 未確定事項をOpen questionsとして残す

## 2. 設計ステータス

- 内部電源構成: 未確定
- 標準電池本数: 未確定
- 保護回路方式: 未確定 / 未検証

本文書は実装Goではない。

## 3. 設計原則

- 電源投入時は出力OFFを既定とする。
- モード選択だけで出力ONにしない。
- 出力ONには明示的な操作を要求する。
- fault時は出力OFFにする。
- fault clearは明示操作とし、自動復帰しない。
- MCU停止、reset、crash、watchdog、boot中でもハードウェアが安全側へ倒れる。
- firmwareは監視、ログ、UI通知、追加制限を担当してよいが、唯一の保護層にしない。
- 測定値の意味、測定パス、単位、処理段階を明記する。
- `unknown` の値を生徒向け判断に使わない。

## 4. ドメイン分割

| ドメイン | 役割 | 注意 |
|---|---|---|
| SYS | ESP32-S3、表示、入力、Wi-Fi AP、設定 | 保護の唯一層にしない |
| MEAS | 電圧・電流測定、フィルタ、校正 | 表示値とCSV値を区別する |
| EXC | 内部電源による出力 | アクティブ出力として扱う |
| TEMP | 温度センサー、Grove等 | センサー種別と配置は未確定 |
| STORAGE / TRANSFER | CSV保存、QR/ローカル転送 | 転送前に出力OFFとCSV close |
| PROTECTION | 短絡、過電流、逆接続、過熱、低電圧、外部電圧印加 | firmware-only禁止 |

## 5. 想定測定パス

基本案:

```text
内部電源候補
  -> 保護回路
  -> 出力制御
  -> 負荷
  -> 電流測定経路
  -> 戻り経路

電圧測定:
  負荷端子間、または定義済みの出力測定点

電流測定:
  負荷に流れる電流を代表する定義済み経路
```

この図は概念であり、回路方式を確定しない。

測定値には少なくとも次を紐づける。

- 内部電源構成
- 出力状態
- 負荷種別
- 電圧測定点
- 電流測定経路
- 保護回路状態
- fault状態

## 6. 負荷カテゴリ

固定抵抗:

- 抵抗値と許容電力を確認する。
- `R = V / I` は測定条件に基づく計算値として扱う。
- 許容電力超過を防ぐ保護が必要。

豆電球:

- 固定抵抗ではなく、温度で抵抗が変わる非線形負荷として扱う。
- `R = V / I` はその条件での見かけの抵抗である。
- 定格電圧・定格電流を超えない保護が必要。
- 発光状態や温度変化により値が変化することを教材上明記する。

発熱体 / 電熱線:

- 抵抗値、定格、発熱条件を確認する。
- 最大電流、最大時間、最大エネルギー制限が必要。
- 火傷、筐体加熱、周辺物加熱を評価する。

温度センサー:

- 発熱実験ロガーの補助値として扱う。
- 温度変化は熱量を直接測定するものではない。
- センサーの設置場所と応答時間を記録する。

## 7. モード別の設計要求

理科モード:

- 主に V と I を表示し、生徒に考えさせる。
- R、P、E は答え合わせまたは分析用として扱う。
- 常時答えを見せない設計を継承する。

技術科モード:

- R、P、消費電力を直接確認できる設計を許容する。
- 固定抵抗、豆電球、発熱体の部品特性比較に使う。
- 値の意味と単位を明示する。

発熱実験ロガーモード:

- V/I/P/time を記録する。
- 電気エネルギー候補値を記録する。
- 温度センサーが有効な場合は温度変化も記録する。
- 出力時間とエネルギー上限を必須とする。

## 8. 出力状態案

状態名はドラフトであり、実装名ではない。

| 状態 | 出力 | 意味 |
|---|---|---|
| SafeDisabled | OFF | 電源投入、reset、終了、fault後の安全状態 |
| OutputArmed | OFF | 出力準備状態。目標値ゼロ、faultなし、明示操作待ち |
| OutputEnabled | ON | 明示操作後のみ出力 |
| Fault | OFF | 保護または異常検出で強制OFF |
| FaultCleared | OFF | 原因除去後に明示操作でクリア。自動ONしない |

ルール:

- 出力目標はゼロから開始する。
- モード離脱時は出力OFFにする。
- QR/ローカル転送前は出力OFF、CSV closeを行う。
- fault clear後も出力はOFFのままにする。

## 9. 保護設計要求

必須:

- 短絡保護
- 過電流保護
- 逆接続保護
- 外部電圧印加検出
- 電池逆挿入保護
- 低電圧保護
- 過熱保護
- 最大電圧制限
- 最大電流制限
- 最大時間制限
- 最大エネルギー制限
- タイムアウト

firmware-only禁止:

- 短絡、過電流、逆接続、電池逆挿入はMCU firmwareだけに依存しない。
- MCU停止、reset、crash、watchdog、boot中でもハードウェアが安全側へ倒れる。
- firmwareは監視、ログ、UI通知、追加制限を担当してよいが、唯一の保護層にしない。

## 10. 内部励起と通常外部測定の排他

内部励起出力と、通常の外部回路測定、USB-C測定、Normal Probe 的な外部測定を同時に有効化してはならない。
内部励起は負荷へ電力を供給できるアクティブ出力であり、外部測定とは安全条件と測定値の意味が異なる。

設計要求:

- 内部励起モードでは、通常外部測定モードと同じ端子・測定経路を無条件に共有しない。
- 通常外部測定モード、USB-C測定、Normal Probe 的な外部測定では、内部励起出力をOFFに保つ。
- モード遷移時には、出力OFF、出力目標ゼロ、fault状態確認を行う。
- 内部励起端子へ外部電圧が印加される誤接続を想定する。
- 外部電圧印加を検出し、保護し、必要に応じてfaultへ遷移する設計を要求する。
- 外部電圧印加時に内部電池へ危険な充電経路や逆流経路ができないようにする。

排他条件、端子共有条件、外部電圧印加検出方法が未確定の場合、内部励起設計を確定してはならない。
本文書では端子構成、回路方式、UI表示名を確定しない。

## 11. CSV / 転送との関係

- CSVは出力状態、fault状態、測定パス、値の意味を記録できる設計が望ましい。
- `REC-*.csv` 互換を壊さない。
- `VI-*.csv`、`HEAT-*.csv` は候補であり未確定。
- `MO-*.csv` は使わない。
- 長いCSVの転送ではチャンク転送を再利用候補とする。
- チャンク転送移植前後に既存 `REC-*.csv` の実機再検証を行う。

## 14. Go / NoGO

Go:

- 内部励起をアクティブ出力として扱う。
- 出力OFF既定、明示ON、fault OFF、明示clearを必須にする。
- 測定パスと測定値の意味を文書化する。
- 保護をfirmware-onlyにしない。
- 内部励起と通常外部測定の排他を設計要求に含める。

NoGO:

- 保護回路未定のまま内部電源設計を確定する。
- 内部励起と通常外部測定の排他条件が未確定のまま設計を確定する。
- 外部電圧印加検出・保護・fault遷移が未定義のまま内部励起をGoにする。
- firmwareだけを短絡・過電流・逆接続・電池逆挿入の保護層にする。
- `MO-*.csv` や Motor Observe 実装を次期本線へ持ち込む。
- 豆電球を固定抵抗として扱う。
- 発熱実験ロガーを熱量測定器として扱う。
