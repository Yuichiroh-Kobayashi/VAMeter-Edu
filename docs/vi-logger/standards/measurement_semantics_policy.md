# 測定セマンティクス方針ドラフト

ステータス: ドラフト / 未確定

本文書は、VAMeter-Edu の次期 V-I 実験器 / V-I ロガー / 発熱実験ロガーで扱う測定値の意味、すなわち測定セマンティクスを定義するための標準文書ドラフトである。
本文書はファームウェア実装、CSVスキーマ確定、UI仕様確定、校正値確定を行わない。

## 1. 目的

測定値は、数値と単位だけでは教材として十分ではない。
どの測定パスで、どの物理量を、どの処理段階の値として扱うかを明示しなければならない。

本方針の目的は次の通りである。

- UI、CSV、文書、ログで測定値の意味を混同しない
- 生値、フィルタ値、校正調整値、表示値、記録値、計算値を区別する
- `unknown` の値を生徒向け判断に使わない
- 豆電球の見かけの抵抗を固定抵抗の抵抗値と混同しない
- 内部電源によるアクティブ出力時の測定パスを明示する

## 2. 適用範囲

対象:

- 電圧測定
- 電流測定
- 電力計算
- 見かけの抵抗計算
- 電力量またはエネルギー候補値の計算
- 温度測定と温度変化
- CSV記録値
- UI表示値
- 校正または補正後の値
- 内部励起出力時の測定値

対象外:

- CSVスキーマの列名確定
- UI画面仕様の確定
- 校正手順の詳細確定
- 保護回路方式の確定
- Motor Observe / MAKER-DRIVE / `MO-*.csv`

## 3. 基本原則

- 測定値には、物理量、単位、処理段階、測定パスを結びつける。
- 表示文字列を内部計算やCSV記録のソースにしない。
- CSV値は、表示フォーマット変更で暗黙的に変わってはならない。
- 計算値は、元にした測定値と式を文書化する。
- 測定パスが不明な値は `unknown` とし、生徒向け判断や教材上の結論に使わない。
- 未確認のファームウェア挙動は `未確認`、未検証のハードウェア挙動は `未検証` と書く。

## 4. 値の段階

少なくとも次の段階を区別する。

| 段階 | 意味 | 注意 |
|---|---|---|
| 生値 | センサーまたはADC等から取得した未加工値 | 単位変換前の場合がある |
| フィルタ値 | 平滑化、平均化、外れ値処理後の値 | 表示・記録どちらに使うかを明記する |
| 校正調整値 | 校正または補正を適用した値 | 表示のみかCSVにも反映するかを分ける |
| 表示値 | UIに表示する値 | 丸め、単位切替、非表示状態を含む |
| 記録値 | CSVに保存する値 | 表示値と同一とは限らない |
| 計算値 | V/I/P/R/E/温度差などの派生値 | 元値、式、条件を明記する |

## 5. 測定パスの記述

測定値には測定パスを紐づける。

例:

- 外部回路の端子電圧
- 負荷へ流れる電流
- 内部励起出力から負荷へ供給される電圧
- 内部励起出力から負荷へ供給される電流
- USB-C電力測定経路
- 温度センサーの設置点

測定パスの記述に最低限含めるもの:

- 電源の種類
- 負荷の種類
- 電圧測定点
- 電流測定経路
- VAMeter-Edu の端子接続
- 内部励起出力のON/OFF状態
- 保護回路または電流制限の状態

## 6. 計算値の扱い

電力:

- `P = V * I` の計算値であることを明記する。
- 元にした V と I が同じ時間・同じ測定パスを代表しているか確認する。
- 過渡状態の値と安定状態の値を混同しない。

抵抗:

- 固定抵抗の場合でも、`R = V / I` は測定条件に基づく計算値である。
- 抵抗器の公称値、許容差、許容電力とは区別する。
- 電流がゼロまたは極小の場合、R計算は無効または要注意とする。

豆電球:

- 豆電球の `R = V / I` は、その条件での見かけの抵抗である。
- 固定抵抗の抵抗値と同じ意味にしない。
- 温度、発光状態、経過時間、電圧、電流により変化する非線形負荷として扱う。
- 理科ではV/Iから考えさせ、技術科では部品特性の確認として扱う。

エネルギー:

- 電気エネルギー候補値は、電力を時間で積算した値として扱う。
- 発熱量を直接測定した値ではない。
- 発熱実験ロガーでは、電気的入力と温度変化の関係を記録するものとする。

温度:

- 温度センサーの種類、設置場所、応答時間、校正状態を記録する。
- 温度差は、基準時刻と測定時刻を明示する。
- 温度値だけから熱量を直接断定しない。

## 7. 符号規約と値の有効性

電圧、電流、電力は、測定パスごとに正方向を定義する必要がある。
正方向が未定義の値、または測定パスと符号規約の対応が不明な値を、生徒向け判断に使ってはならない。

内部励起では、少なくとも次の扱いを設計前に定義する必要がある。

- 内部電源から負荷へ電力を供給する向きを正とするか。
- 外部電圧が内部励起端子へ印加された場合の値をどう扱うか。
- 逆向き電流が検出された場合に、測定値、保護状態、fault状態をどう扱うか。
- 出力OFF中に観測された電圧・電流を有効値とするか、保護判定専用値とするか。

これらは未確定事項であり、本文書ではCSV列名やUI表示名を確定しない。

各値には、有効性状態を結びつける方針とする。
候補状態は次の通りであり、名称は未確定である。

| 状態候補 | 意味 |
|---|---|
| `valid` | 測定パス、符号規約、範囲が定義済みで、教材判断に使える候補値 |
| `invalid` | 条件不成立により使ってはならない値 |
| `unknown` | 測定パス、符号規約、処理段階、または値の意味が未確認 |
| `range_over` | 測定範囲を超えた可能性がある値 |
| `saturated` | センサー、ADC、計算、または表示が飽和した値 |
| `fault` | fault中またはfault原因に関連する値 |
| `output_off` | 出力OFF中の値。教材値か保護判定値かは未確定 |

有効性状態が `valid` 以外の値は、原則として生徒向けの結論、正誤判定、部品評価、発熱実験の考察結果に直接使わない。

## 8. UIでの扱い

理科モード:

- 基本は V と I から考えさせる。
- R、P、Eなどの計算値は常時表示しない設定を許容する。
- 答え合わせUIにより、必要なときだけ計算値を表示できる設計を検討する。

技術科モード:

- R、P、消費電力を直接確認できる表示を許容する。
- ただし、表示するRが固定抵抗の公称値か、測定条件での見かけの抵抗かを明確にする。

発熱実験ロガーモード:

- 電力、時間、電気エネルギー候補値、温度を分析用に扱う。
- 発熱量を直接測定したかのような表示を避ける。

## 9. CSVでの扱い

CSVでは次を満たす必要がある。

- 値の単位を列名またはスキーマ文書で明示する。
- 生値、表示値、記録値、計算値のどれかを明示する。
- 測定パスまたは測定モードを識別できるようにする。
- `unknown` の測定パスやセマンティクスを含む場合、教材判断に使わない。
- `REC-*.csv` 互換を壊さない。
- `MO-*.csv` を次期CSVスキーマの基準にしない。
- `VI-*.csv`、`HEAT-*.csv` などのプレフィックスは候補であり未確定とする。
- 符号規約と値の有効性状態を記録する方針を検討する。ただし列名は本ドラフトでは確定しない。

### 9.1 現行PR #1実装の電流値契約

次は将来設計ではなく、merge commit `c9bb8ca`時点の現行実装を説明する。

- application-levelの`POWER_MONITOR::PMData_t::shuntCurrent`はA単位である。
- current CSV列もA単位で、HALが提供する処理済み`shuntCurrent`を追加補正せず記録する。
- screen表示とCSVは同じHAL `shuntCurrent`を起点とする。screenの`uA`／`mA`／`A`切替は表示formatである。
- Waveformの`_pm_data_a_scale = 1000`はchart内部の数値精度確保用であり、measurement calibration、shunt係数、または単位補正ではない。
- single-channel plotの0 baseline clipはUI描画だけに作用し、UIが受け取ったHAL値やCSVへ渡す値を書き換えない。
- ただし、UIへ到達する前のHAL測定経路にはrange固有処理がある。high-current reverse measurement経路はnegative currentを保持できるが、low-current経路はcurrent offset適用後のnegative valueを既存HALで`0 A`へclampする。
- したがって「全rangeでnegative raw currentがCSVへ残る」とは表現しない。CSVに保存されるのはsensor registerの未加工raw値ではなく、HAL処理後の値である。

UIまたはCSVの観察から、1000倍補正、INA226 calibration、LC/HC切替、offset、shunt係数を推測で変更してはならない。これらは別のhardware/calibration taskとして、測定pathと根拠を確認して扱う。

## 10. 禁止事項

- 表示値をそのまま測定の真値として扱う。
- UI名や画面色から測定パスを推測する。
- `unknown` の値を生徒向け判断に使う。
- 符号規約が未定義の電圧、電流、電力を教材判断に使う。
- `valid` 以外の有効性状態の値を、条件説明なしに正しい測定値として扱う。
- 豆電球の見かけの抵抗を固定抵抗の抵抗値として扱う。
- 発熱実験ロガーの電気エネルギー候補値を、直接測定した熱量として扱う。
- Motor Observe の測定語彙や `MO-*.csv` を次期製品の標準として流用する。

## 12. Go / NoGO

Go:

- 測定値の意味を文書化する。
- 生値、フィルタ値、表示値、記録値、計算値を区別する。
- `unknown` を教材判断に使わない。
- 豆電球を非線形負荷として扱う。
- 符号規約と値の有効性状態を設計対象に含める。

NoGO:

- 測定パス不明のまま製品仕様を確定する。
- 符号規約未定義の値を教材判断に使う。
- CSVスキーマを本ドラフトで確定する。
- UI仕様を本ドラフトで確定する。
- 保護未検証のアクティブ出力を使用可能と記述する。
