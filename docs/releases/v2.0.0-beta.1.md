# v2.0.0-beta.1

Released 2026-08-21. This is a beta prerelease, not stable `v2.0.0`. See
[`CHANGELOG.md`](../../CHANGELOG.md) for the canonical entry this record expands on.

## Added

Device-hosted same-origin Viewer with Student / Professional modes, Voltage / Current /
Both display profiles, and 10 / 30 / 60 second display windows. See
[`device-hosted-viewer-contract.md`](../product/device-hosted-viewer-contract.md) for the
full current contract, and
[`../architecture/systemlive-lifecycle-and-ownership.md`](../architecture/systemlive-lifecycle-and-ownership.md) /
[`../architecture/viewer-assetpool-integration.md`](../architecture/viewer-assetpool-integration.md)
for the underlying architecture.

## Changed

The fallback educational recording duration is fixed at five seconds; recorded CSV uses
the existing local download workflow. See
[`../product/educational-recording-and-local-download.md`](../product/educational-recording-and-local-download.md).

## Validated

Physical Viewer validation was performed on Windows Edge 151 and an iPad 7th generation
running iPadOS 18.7.9 Safari; this is the `v2.0.0-beta.1` physical-validation evidence per
the [`CHANGELOG.md`](../../CHANGELOG.md) entry. These browser tests validated the
Viewer/D2B path; they did not re-qualify electrical measurement accuracy.
[`browser-physical-qualification.md`](../validation/browser-physical-qualification.md) is
the current qualification procedure for future browser/Viewer testing; it was written
after this release and is not a claim about the specific steps followed to produce this
`v2.0.0-beta.1` evidence.

## Known limitations

- Application and AssetPool binaries must be used as the matched `v2.0.0-beta.1` pair —
  see [`../architecture/viewer-assetpool-integration.md`](../architecture/viewer-assetpool-integration.md)
  for why the Viewer bundle and AssetPool are a byte-exact matched contract.
- [Issue #3](https://github.com/Yuichiroh-Kobayashi/VAMeter-Edu/issues/3) remains open;
  gap-free CSV and uniform sampling are not claimed.
- Static IRAM usage is `16383 / 16384` bytes; resource headroom is extremely limited and
  must be reviewed before adding firmware features — see
  [`../architecture/resource-budget.md`](../architecture/resource-budget.md).
- This is a beta prerelease, not stable `v2.0.0`.
